# Minifeel 导演式创作工作台设计

## 目标

将普通用户的项目入口改造成导演式分步创作工作台，让不了解 AI、Agent、Skill、节点和工作流的用户，只需输入一句话并依次确认剧本、角色、分镜和成片，即可完成一条短剧。

本次改造保留 Toonflow 现有画布、节点、Agent、文档、素材和生成能力，将它们作为底层创作能力和高级模式。普通创作页与高级画布共用同一个项目目录和业务数据，不建立第二套项目格式或工作流引擎。

成功标准：

- 普通用户从创作首页输入一句话后进入分步创作页，不再落到空白高级画布。
- 用户能够生成、检查和修改剧本、角色、分镜，并发起视频生成任务。
- 图片、视频等生成操作在执行前明确展示模型、数量和预计积分，并要求用户确认。
- 普通创作页与高级画布的数据保持一致，刷新页面后可恢复进度。
- 原 Toonflow 高级画布继续可用，现有节点和 Agent 能力不被删除。

## 用户与权限

本工作台面向普通用户。普通用户只看到管理员已经启用并公开的模型名称，不能查看或修改供应商地址、API Key、计费规则和底层模型参数。

管理员继续在独立管理页面维护供应商、密钥、模型、启用状态和积分价格。普通创作页读取管理员当前配置；管理员停用模型后，新任务不能再选择该模型，已有任务和历史结果仍可查看。

视频任务也必须经过生成确认。预计积分由管理员配置决定；当前价格为零时，确认页显示“本次消耗 0 积分”。

## 路由与入口

路由行为调整如下：

| 路径 | 用途 |
| --- | --- |
| `/app` | 普通用户创作首页和项目列表 |
| `/app/projects/:projectId` | 导演式分步创作工作台 |
| `/app/projects/:projectId/advanced` | Toonflow 高级画布 |

首页点击“开始创作”后，系统创建项目、保存初始需求并进入 `/app/projects/:projectId`。项目列表中的已有项目也默认进入该地址。

高级画布作为项目顶部更多菜单中的次级入口。用户从高级画布返回时进入同一项目的普通创作页，不返回其他项目或创建新项目。

## 页面结构

工作台使用左侧阶段导航、中央创作内容和右侧导演助手三栏结构。

### 顶部项目栏

顶部项目栏展示：

- 返回创作首页。
- 项目名称。
- 当前阶段。
- 自动保存状态。
- 项目预览入口。
- 包含高级画布入口的更多菜单。

保存状态区分保存中、已保存和保存失败。保存失败时提供重试入口，并阻止用户在不知情的情况下丢失修改。

### 左侧阶段导航

固定展示四个阶段：

1. 剧本。
2. 角色。
3. 分镜。
4. 成片。

阶段状态统一为：

- `notStarted`：尚未开始。
- `running`：正在生成或处理。
- `review`：已有草稿，等待用户检查。
- `complete`：用户已确认。
- `failed`：本阶段存在失败任务。

状态优先从项目内容和生成任务推导。页面不维护一套与画布文件相互独立、可能产生冲突的创作数据。

### 中央创作内容

中央区域只展示当前阶段需要用户处理的内容。用户切换阶段时保留未提交的本地编辑状态；离开项目或切换到高级画布前必须完成保存队列。

### 右侧导演助手

导演助手复用现有 Agent 会话、流式响应和工具调用能力，界面只显示：

- 用户需求和助手建议。
- 当前正在完成的创作步骤。
- 可理解的进度信息。
- 失败原因和可执行的下一步。
- 针对当前剧本、角色或镜头的修改入口。

普通模式不展示节点标识、工具名称、Skill、上下文长度、供应商请求或原始工具参数。完整工具执行信息继续保留在高级画布和服务端日志中。

## 创作阶段

### 剧本阶段

剧本阶段展示标题、故事概要、类型与风格、分场内容、台词和预计时长。用户可以直接修改文字，也可以选中内容要求导演助手局部调整。

一句话创作完成后，系统首先生成剧本草稿，并将阶段置为 `review`。用户确认后，系统提取角色、场景和必要道具，进入角色阶段。

### 角色阶段

每个角色使用角色卡展示名称、身份、性格、外貌、服装、参考图片和关联分镜数量。

用户可以编辑角色设定、上传参考图、生成角色图片、重新生成单个角色并锁定最终形象。锁定的角色设定作为后续分镜生成的统一参考，降低跨镜头人物不一致。

### 分镜阶段

每个镜头使用分镜卡展示镜头编号、场景、角色、景别、动作、台词、预计时长、分镜图片和任务状态。

用户可以编辑单个镜头、调整镜头顺序、重新生成单个分镜、批量生成尚未生成的分镜图片，并选择镜头发起视频任务。局部操作只更新对应镜头，不覆盖已经确认的其他镜头。

第一版不增加专业时间线、多轨编辑和复杂镜头参数面板。

### 成片阶段

成片阶段展示视频任务列表、各镜头处理进度、失败镜头、视频片段预览、最终结果和下载入口。

第一版沿用现有视频任务与结果管理能力，不新增完整剪辑器、配音编辑器、字幕时间线或复杂转场系统。

## 一句话自动创作

完整流程如下：

1. 用户在首页输入故事想法。
2. 系统创建项目并保存初始需求。
3. 页面进入导演式创作工作台。
4. 工作台准备共享项目运行层和 Agent 会话。
5. 系统发送初始需求，生成剧本草稿。
6. 系统提取角色、场景和道具清单。
7. 系统生成文字分镜草稿。
8. 页面停在剧本检查状态，等待用户确认和修改。
9. 用户确认内容后，再发起需要图片或视频模型的任务。

初始自动流程只生成文本草稿，不在没有用户确认的情况下连续消耗图片或视频积分。

## 生成确认与积分

批量图片生成、角色形象生成和视频生成在执行前使用统一确认界面，展示：

- 生成类型。
- 生成对象和数量。
- 管理员启用的模型名称。
- 预计消耗积分。
- 用户当前积分。
- 执行后的预计剩余积分。

积分不足时不允许提交任务，并引导用户联系管理员或等待后续充值能力。确认后沿用现有积分冻结、任务结算和失败退款逻辑，不在前端自行扣减积分。

## Toonflow 复用架构

### 单一数据来源

普通创作页和高级画布共享：

- 项目目录。
- 画布文件。
- Agent 会话记录。
- 生成任务。
- 素材与生成结果。
- 用户积分记录。

`guided` 和 `advanced` 只表示展示模式，不产生两份项目数据。

### 创作视图适配

普通创作页增加一层创作视图适配逻辑，将现有画布内容转换为剧本、角色、分镜和成片页面需要的数据。适配逻辑负责读取和映射，不直接通过字符串或未经校验的对象拼接画布 JSON。

用户在普通创作页执行修改和生成操作时，调用现有 Store、画布控制接口和 Agent 工具。所有文件读写复用 `useWorkspaceFiles`，保存队列在开始时取得项目目录快照，避免切换项目后写入错误目录。

### 共享运行层

现有部分节点工具依赖已经挂载的 VueFlow 运行环境。普通创作页内部复用现有画布运行层，提供固定尺寸并排除普通用户的交互与无障碍访问，而不是使用会让 VueFlow 无法计算尺寸的 `display: none`。

实施阶段先验证现有工具在该运行方式下是否能够初始化和保存。如果个别工具仍要求真实可见画布，只将对应状态控制从渲染组件提取为共享模块；不重写整个工作流引擎，也不直接绕过工具修改画布文件。

## 前端组件边界

在现有 `apps/web/src/pages/project` 基础上渐进改造。预计组件职责如下，只有在职责足够独立时才新建文件：

- `projectHeader.vue`：项目导航、名称、保存状态、预览和高级画布入口。
- `projectStages.vue`：阶段导航和阶段状态。
- `scriptStage.vue`：剧本展示与编辑。
- `characterStage.vue`：角色卡和角色确认。
- `storyboardStage.vue`：分镜卡和镜头操作。
- `filmStage.vue`：视频任务、预览和下载。
- `directorPanel.vue`：普通用户使用的导演助手界面。
- `generationConfirm.vue`：生成前模型、数量和积分确认。
- `projectRuntime.vue`：复用现有画布运行能力。
- `creativeViewAdapter.ts`：画布内容到阶段数据的映射。

简单逻辑保留在已有组件中，不为了目录结构提前创建空组件或无业务价值的抽象层。

## 保存、同步与恢复

普通创作页的修改进入现有项目保存流程。进入高级画布、返回首页、关闭项目或浏览器刷新前，统一等待当前保存队列完成。

保存失败时：

- 页面显示明确错误。
- 用户可以重试保存。
- 普通退出操作不会静默丢弃修改。
- 只有用户选择强制退出时才放弃未保存内容。

高级画布保存后，普通创作页重新读取项目内容并更新阶段卡片。普通创作页保存后，高级画布读取同一画布文件，因此不需要额外同步副本。

刷新页面时重新读取项目文件、Agent 会话和任务状态，恢复当前阶段和生成进度。运行中的生成任务继续由后端任务状态决定。

## 错误处理

错误显示在对应阶段、角色卡、分镜卡或成片任务上，内容包含：

- 失败的对象。
- 用户可以理解的失败原因。
- 积分是否已退回或未扣除。
- 重试或修改输入的下一步操作。

前端不直接展示第三方供应商的长错误堆栈、请求体或密钥信息。原始错误保留在服务端日志和管理员调试页面中。

导演助手失败不应使已经保存的剧本、角色和分镜消失。单个生成任务失败不应阻塞其他已完成内容的查看和编辑。

## 第一版范围限制

第一版不包含：

- 专业视频时间线和多轨剪辑。
- 自动配音编辑器。
- 字幕逐字校准。
- 复杂转场系统。
- 普通用户自定义工作流。
- 普通用户配置 API 或计费规则。
- 新的后端工作流引擎。
- 支付接口。

这些能力不提前创建占位页面、模拟接口或无业务逻辑的组件。

## 验证方案

仓库禁止新增测试文件。本次改造使用现有类型检查、构建和手动冒烟验证：

1. 执行受影响工作区的类型检查。
2. 执行 Web 与 Server 构建。
3. 使用普通测试账号从首页输入一句话并创建项目。
4. 验证项目进入普通创作页，而不是高级画布。
5. 验证剧本生成、修改、保存和刷新恢复。
6. 验证角色提取、角色图片确认和单项重试。
7. 验证分镜编辑、排序、批量确认和生成任务状态。
8. 验证生成确认中的模型、数量和积分。
9. 在视频调用频率允许时生成约 15 秒短片；频率受限时验证任务提交前的完整流程和任务状态恢复。
10. 验证普通创作页和高级画布读取同一项目数据。
11. 验证保存失败、退出拦截和强制退出行为。

## 实施阶段

### 阶段一：工作台入口与外壳

- 修正首页和项目列表的默认路由。
- 完成三栏工作台、四阶段导航和高级画布入口。
- 验证项目创建、打开、返回和刷新。

### 阶段二：剧本与角色

- 接入现有 Agent 会话。
- 自动生成并编辑剧本草稿。
- 提取、展示和确认角色。
- 接入角色形象生成。

### 阶段三：分镜与生成确认

- 展示和编辑分镜卡。
- 支持调整顺序和单项重新生成。
- 增加图片、视频生成前确认和积分展示。

### 阶段四：成片与保存收尾

- 接入视频任务状态、失败重试、预览和下载。
- 统一普通模式与高级模式的保存、退出和刷新恢复。
- 完成全流程冒烟验证并记录未解决问题。

### 阶段五：部署验证

- 提交并推送通过验证的代码。
- 使用生产 Compose 配置重新构建并启动服务。
- 保留生产数据库、项目文件和管理员配置挂载目录。
- 使用普通测试账号验证线上路由、登录和完整创作流程。

每个开发阶段完成后更新实施计划文档，按中文 Conventional Commits 单独提交并推送到 `dev`。部署在功能实现和本地验证完成后进行。

## 验收标准

- 普通用户无需理解 Agent、Skill、节点、工作流或 API Key。
- 一句话能够创建项目并进入导演式工作台。
- 用户能够生成、修改和确认剧本。
- 用户能够管理角色并生成角色图片。
- 用户能够编辑分镜并生成分镜素材。
- 消耗积分的操作必须经过明确确认。
- 用户能够发起视频任务并查看结果。
- 项目刷新后数据和任务进度能够恢复。
- 普通创作页与高级画布使用同一份项目数据。
- 高级画布原有能力继续可用。
- 类型检查与构建通过。
- 不出现明显白屏、卡死、无法退出或静默丢失数据问题。
