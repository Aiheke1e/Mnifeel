# Minifeel 自托管 Web 迭代设计

## 目标

将现有 Minifeel 改造成可在本地独立运行、后续可部署上线的多用户 Web 应用。产品自身的账号、权限、项目、文件、模型配置、积分、任务和统计全部由本地服务提供，不再依赖 `api.minifeel.net` 或其他 Minifeel 外部服务。

运行时仅允许以下三类外部模型请求：

- DeepSeek 文本模型。
- Agnes 视频模型。
- BananaPro 图片模型。

普通用户无需理解供应商、API、Agent、Skill、节点或工作流。管理员统一配置供应商、密钥、可用模型和积分价格，用户只选择管理员启用的模型。

## 本期范围

本期包含：

- Web 用户账号、模拟验证码登录、密码登录和模拟 Google 登录。
- 管理员初始化、角色跳转和独立管理后台。
- PostgreSQL 持久化。
- 用户项目和本地文件隔离。
- 供应商密钥加密、模型网关和三家供应商适配。
- 积分账户、积分流水、预冻结、结算和失败退款。
- 可恢复的文本、图片和视频生成任务。
- 用户端与管理端 UI 重构。
- 移除外部 Minifeel 登录、模型中转、充值、插件市场、赞助商和遥测。
- 保留现有画布、文档、Agent、节点和项目文件格式。

本期不包含：

- 真实短信服务。
- 真实 Google OAuth。
- 微信、支付宝或其他支付渠道。
- 云对象存储。
- Redis、消息队列或微服务拆分。
- 自动配音、自动字幕和最终成片剪辑的新业务能力。
- 重新实现已经跑通的画布与短剧生成业务。

## 部署结构

正式运行包含两个核心服务：

1. Minifeel 应用服务：Bun、Express、Vue 静态页面、API、模型网关和任务 Worker。
2. PostgreSQL：结构化业务数据。

项目文件和生成素材保存在应用服务挂载的本地数据目录，不单独部署对象存储。

```text
浏览器
  -> Minifeel 应用服务
       -> PostgreSQL
       -> data/workspaces/{userId}/{projectId}/
       -> DeepSeek API
       -> Agnes API
       -> BananaPro API
```

开发时分别运行 Vite、Bun Server 和 PostgreSQL。生产构建继续由 Express 提供 `build/web` 静态文件。

## 代码结构

沿用现有仓库结构，在 `apps/server` 和 `apps/web` 内渐进扩展，不新建第二套后端。

服务端增加以下职责边界：

- `utils/database/`：数据库连接、迁移和事务入口。
- `utils/auth/`：密码、验证码、会话和身份解析。
- `utils/secrets/`：供应商密钥加密和解密。
- `utils/billing/`：积分账户、流水、冻结和结算。
- `utils/generation/`：任务入队、Worker 和任务状态。
- `utils/providers/`：统一供应商适配入口。
- `routes/auth/`：登录、注册、登出、密码和当前用户接口。
- `routes/admin/`：管理员用户、供应商、模型、积分、任务和统计接口。
- `routes/projects/`：按当前用户处理项目和素材。

`routes/` 继续遵守一个接口一个文件，新增或移动路由后使用现有路由生成器更新 `router.ts`。

前端增加以下页面边界：

- `pages/login/`：统一登录与注册。
- `pages/app/`：普通用户首页和任务中心。
- `pages/admin/`：独立管理员后台。
- `pages/project/`：现有工作区的新用户外壳。

现有画布、文档、节点和 Agent 组件继续复用。普通模式隐藏技术入口，高级模式再展示现有画布和 Agent。

## 数据库

使用 PostgreSQL。服务端采用轻量 PostgreSQL 客户端和显式迁移，不引入大型服务框架。密码哈希使用 Bun 自带的密码 API，随机令牌和密钥加密使用 `node:crypto`。

主要数据表如下。

### users

- 用户 ID。
- 角色：`admin` 或 `user`。
- 状态：正常或禁用。
- 是否白名单。
- 可选密码哈希。
- 创建和更新时间。

白名单是用户状态，不是管理员角色。白名单用户不能修改供应商或模型配置。

### userIdentities

- 所属用户。
- 身份类型：手机号、模拟 Google 或真实 Google。
- 规范化后的唯一标识。
- 第三方主体 ID，可为空。
- 验证时间。

手机号按国家或地区代码规范化。V1 模拟 Google 身份与未来真实 Google 身份分开保存，避免把未验证邮箱当作真实 OAuth 身份。

### userSessions

- 所属用户。
- 会话令牌哈希。
- 创建、最近使用、过期和撤销时间。
- 浏览器与来源的有限描述信息。

浏览器只持有随机会话令牌，数据库只保存哈希。Cookie 使用 `HttpOnly`、`SameSite=Lax`，生产 HTTPS 下启用 `Secure`。每个账号最多保留两个有效会话，新登录成功后撤销最早的会话。

### verificationCodes

- 手机号。
- 用途：登录、设置密码或重置密码。
- 验证码哈希。
- 过期和消费时间。

V1 后端仍生成六位随机码并输出到服务端日志。当 `MINIFEEL_AUTH_MOCK_CODE=true` 时，任意非空验证码都可通过；关闭后必须验证真实生成的验证码。短信发送封装成独立接口，后续接入真实服务时不改变登录路由。

### providerConfigs

- 供应商类型：DeepSeek、Agnes 或 BananaPro。
- 显示名称、基础地址和启用状态。
- 加密后的 API Key、随机 IV 和认证标签。
- 最近连接测试结果和时间。

API Key 使用 AES-256-GCM 加密。主密钥由 `MINIFEEL_SECRET_KEY` 环境变量提供，不写入数据库、日志、前端响应或仓库。

### modelConfigs

- 所属供应商。
- 上游模型 ID、用户显示名称和媒体类型。
- 是否启用、是否默认。
- 能力配置，例如图片比例、视频时长和分辨率。
- 积分计价配置。

同一媒体类型只能有一个默认模型。用户只读取启用模型的安全字段，不能读取供应商密钥和内部请求配置。

### creditAccounts 与 creditTransactions

`creditAccounts` 保存可用积分和冻结积分，用于高频读取；`creditTransactions` 保存不可修改的完整流水。

流水类型包括：

- 管理员赠送。
- 任务冻结。
- 任务结算。
- 任务退款。

管理员只能创建正数赠送流水，不能直接覆盖余额，也不能删除或修改已有流水。本期不提供支付充值和人工扣减。

### projects 与 projectAssets

`projects` 保存项目归属、名称、状态和磁盘相对目录。`projectAssets` 保存素材的项目归属、相对路径、类型、大小和创建时间。

数据库只保存索引，画布、文档、Agent 会话和媒体内容继续使用现有文件格式。

### generationTasks

- 所属用户、项目和模型。
- 任务类型：文本、图片或视频。
- 状态：等待、运行、成功、失败或取消。
- 幂等键。
- 安全处理后的请求摘要和结果文件。
- 冻结积分、实际积分和退款积分。
- 错误码、用户可见错误信息、创建和完成时间。

任务记录不得保存 API Key、Authorization、Cookie 或其他密钥字段。

### auditLogs

记录管理员登录、模型配置、积分赠送、用户禁用、会话撤销和查看用户项目等操作。审计记录不可由管理页面修改或删除。

## 账号与权限

所有登录方式共用一个登录页面。

### 手机号验证码

用户输入手机号和任意非空验证码即可在模拟模式中登录。手机号不存在时自动注册，初始积分为 0；手机号存在时直接登录。禁用用户不能创建会话。

### 密码

用户登录后可以设置密码。未设置密码时，账户页面显示安全提醒。设置密码后可通过手机号和密码登录。忘记密码使用手机号验证码重置。

### Google 登录

V1 仅在 `MINIFEEL_AUTH_MOCK_GOOGLE=true` 时展示模拟 Google 登录，用户输入邮箱后创建模拟身份。V2 接入真实 Google OAuth 时增加真实 Google 身份，不把模拟身份自动升级为已验证 OAuth 身份。

### 管理员初始化

应用首次启动且数据库没有管理员时，从 `MINIFEEL_ADMIN_PHONE` 和 `MINIFEEL_ADMIN_PASSWORD` 创建管理员。初始化完成后不因环境变量变化覆盖已有管理员密码。

### 授权规则

- `admin` 进入管理后台，可以管理用户、白名单、会话、供应商、模型、积分赠送、任务和统计。
- `user` 进入创作端，只能访问自己的项目、素材、Agent 会话和任务。
- 白名单用户仍属于 `user`，但视频任务消费积分为 0。
- 所有用户只能选择管理员启用的模型。
- 只有管理员能写入供应商、API Key、模型能力和价格配置。
- 管理员打开用户项目时必须写入审计日志。

服务端鉴权以数据库会话为准，不信任前端角色、用户 ID、目录或请求头声明。

## 项目与文件隔离

浏览器不再传递服务器绝对目录。用户端使用 `projectId`，服务端根据会话用户解析到：

```text
data/workspaces/{userId}/{projectId}/
```

所有文件读写继续复用现有路径规范化、符号链接防护、原子写入和文件锁逻辑，并在解析工作区之前增加项目所有权检查。

前端保留 `useWorkspaceFiles` 作为统一入口，将目录参数替换为项目身份。防抖、保存队列和跨 `await` 操作继续在开始时固定项目快照，避免切换项目后写入错误位置。

旧项目不自动移动。用户通过“导入旧项目”明确选择服务器工作区中的旧目录，服务端验证后复制到新项目目录，原目录保留。

## 模型网关

模型网关向上提供统一的文本、图片和视频调用接口，向下封装三家供应商差异。

### DeepSeek

复用现有 OpenAI 兼容文本调用能力，将默认配置从用户设置迁移到管理员供应商配置。管理员同步模型列表、选择启用模型并设置价格。

### Agnes

实现独立视频供应商适配器。适配器支持连接测试、模型同步、创建任务、轮询状态、取消信号和结果下载。由于公开页面不提供完整接口结构，管理员只有在实际密钥完成连接测试并成功同步模型后才能启用模型，不硬编码未经验证的模型 ID。

### BananaPro

实现独立图片供应商适配器。适配器支持连接测试、模型同步、文生图、参考图、取消信号和结果下载。管理员只有在连接测试成功后才能启用模型。

三家供应商的基础地址提供内置默认值，同时允许管理员修改。修改地址或密钥后，已启用模型继续保留，但供应商进入“待重新测试”状态；测试成功前不能发起新任务。

供应商调试信息继续复用现有密钥脱敏逻辑。响应、错误和日志中的常见密钥字段与查询参数必须被遮盖。

## 积分计费

新用户初始积分为 0。管理员通过后台创建正数赠送流水。

普通用户发起任务时：

1. 校验模型启用状态和项目归属。
2. 根据请求计算最大预计积分。
3. 在数据库事务中冻结积分并创建任务。
4. Worker 调用供应商。
5. 成功后按实际用量结算并退回多余冻结积分。
6. 失败、取消或超时后退回全部冻结积分。

文本根据输入和输出 token 价格计算，冻结值使用输入估算和模型最大输出上限。图片按生成张数计算。视频按管理员配置的每次任务或每秒价格计算。

白名单用户的视频任务仍创建任务和用量记录，但冻结与实际消费均为 0。其文本和图片任务继续按普通价格计费。

所有余额变更和任务状态变更使用数据库事务。任务幂等键防止重复点击和网络重试造成重复扣费。

## 任务 Worker

Worker 与应用服务运行在同一 Bun 进程，使用 PostgreSQL 任务表领取工作，不新增 Redis。

- 同一任务只能被一个 Worker 领取。
- 运行任务定期更新时间戳。
- 应用重启后，超过期限且没有心跳的运行任务标记失败并退款。
- 不对供应商错误无条件重试。
- 供应商已有的异步任务轮询在同一任务上下文中继续使用。
- 页面刷新后通过任务接口恢复进度和结果。
- 用户取消任务时触发 AbortSignal；是否能取消上游由供应商能力决定，但本地状态和退款必须一致。

第一阶段按单机、约 100 个同时在线用户设计。并发数由管理员配置，避免本地资源或供应商限额被瞬间打满。

## 用户端 UI

### 登录页

同一页面提供手机号验证码、手机号密码和模拟 Google 登录。页面不出现 API、供应商或模型配置说明。

登录后根据角色跳转：管理员进入 `/admin/dashboard`，普通用户进入 `/app`。

### 创作首页

首页包含：

- 开始创作。
- 最近项目。
- 内置模板。
- 当前积分。
- 最近生成任务。

创建项目时只要求名称、创作描述和模板。服务器自动创建工作区，不让用户选择服务器绝对目录。

### 项目工作区

项目页使用面向创作流程的外壳，复用现有业务组件。普通模式展示当前阶段、内容、模型选择、生成状态和下一步操作。高级模式才展示现有无限画布和 Agent。

本期不重写现有短剧生成逻辑，也不新增自动配音、字幕合成或成片剪辑能力。

### 任务中心与账户页

任务中心显示等待、运行、成功、失败和取消状态，以及消费或退款积分。账户页显示手机号、密码设置状态、登录会话、积分余额和积分流水。

## 管理端 UI

管理端使用与用户端不同的页面框架，但复用基础组件和主题变量。

- 仪表盘：用户数、项目数、任务数、成功率、积分消费和磁盘占用。
- 用户管理：状态、白名单、赠送积分、有效会话和项目摘要。
- 供应商管理：基础地址、密钥、连接测试和同步模型。
- 模型管理：显示名称、启停、默认模型、能力和积分价格。
- 任务管理：状态、供应商、用户、耗时、消费、退款和脱敏错误。
- 审计记录：管理员敏感操作。

管理员不能直接覆盖用户余额。用户项目默认只显示摘要；管理员明确进入项目时记录审计日志。

## 外部依赖清理

删除或停用以下运行时依赖：

- `api.minifeel.net` 登录 iframe。
- TF-Router 文本和媒体供应商。
- TF 余额、充值、订单和插件市场接口。
- 外部赞助商接口。
- 匿名遥测上报。
- 桌面更新、WebView2 和桌面协议入口。
- 用户端供应商与 API Key 配置。
- 默认联网搜索和网页抓取工具。
- 外部插件安装入口和外部插件市场。
- 应用内飞书、企业微信和腾讯文档入口。

FFmpeg 不在运行时从镜像站下载。开发环境安装一次，部署产物或容器镜像中包含可执行文件及其许可证。

构建阶段仍需要包管理器下载开源依赖；构建完成后的业务运行不依赖上述外部产品服务。

## 安全与错误处理

- 所有业务 API 要求有效会话，登录和验证码接口除外。
- 所有管理员 API 使用统一管理员中间件。
- 所有项目和任务接口校验资源所有权。
- Cookie、验证码、密码、API Key 和供应商响应中的密钥字段不得写入日志。
- API Key 解密只发生在服务端供应商调用前。
- 登录、验证码和供应商测试接口执行速率限制。
- 数据库事务失败时不返回成功。
- 文件写入继续使用原子替换和现有错误映射。
- 供应商失败返回用户可理解的错误，详细脱敏信息保留在任务记录中。
- 应用启动时验证数据库连接、密钥主密钥和必要数据目录；缺失时明确失败，不以空配置继续运行。

## 本地开发环境

当前机器已有 Git、Node.js 和 npm，缺少 Bun、Docker 和 PostgreSQL。

实施阶段先安装与仓库声明一致的 Bun 版本。PostgreSQL 采用一个本地实例；优先使用 Docker 容器，若当前 Windows 环境不能启用 Docker，则安装本地 PostgreSQL 服务。只选择一种方式，不同时维护两套本地数据库。

真实模型密钥不进入仓库。仓库只新增环境变量示例；管理员在本地后台填写已重新生成的密钥后执行供应商连接测试。

## 迁移顺序

1. 建立数据库、环境配置和迁移入口。
2. 建立账号、会话、管理员和模拟登录。
3. 建立项目归属与文件隔离。
4. 建立供应商密钥、模型配置和管理员接口。
5. 接入 DeepSeek、Agnes 和 BananaPro。
6. 建立积分流水和生成任务 Worker。
7. 将现有生成入口迁移到任务与计费流程。
8. 重构用户端登录、首页、项目页和任务中心。
9. 建立管理员后台。
10. 移除外部 Minifeel 与桌面端 UI 依赖。
11. 完成旧项目主动导入和实际流程验证。

每个阶段保持可构建，并在执行计划中记录状态、实际改动、验证结果和剩余事项。

## 验证

仓库规范禁止新增测试文件，因此不创建 `.test.ts`、`.spec.ts` 或其他测试文件，也不新增测试框架。

按阶段执行：

- 服务器路由变更后运行 `bun run routes`。
- 执行受影响工作区的类型检查。
- 执行 Web 和 Server 构建。
- 使用临时数据库与临时数据目录进行实际 HTTP 验证。
- 验证模拟手机号注册、密码设置、两会话限制和角色跳转。
- 验证普通用户不能读取或修改供应商配置。
- 验证不同用户不能读取彼此项目和文件。
- 验证管理员赠送积分产生流水且不能直接覆盖余额。
